# 書誌情報の追加 要件

蔵書に NDL サーチの書誌情報(件名、NDC、紙版の刊行年月、出版社など)を付け、Claude が SQL で蔵書を探すときの手がかりを増やす。語の意味は `docs/glossary.md` に従う。v0.4.0 で実装し、確定した仕様は `docs/spec.md` の「書誌情報」に移した。本書はその理由と経緯の記録として残す。

## 背景と前提

- Kindle ASIN から ISBN を得る正攻法はない。Amazon の PA-API 5.0 は廃止され、後継の Creators API は直近 30 日で適格売上 10 件が利用条件のため、個人のツールでは使えない。商品ページの取得は規約で禁止されている見込み。このため、書名と著者で NDL サーチを検索して紙版に照合する。
- 蔵書 2,712 冊のうち約 73% はジャンル「コミック・ラノベ・BL」に属する。ただし `genres` が空のマンガもあり、ジャンルだけではマンガを判別しきれない。

## 取得元

NDL サーチの OpenSearch だけを使う。

| 候補 | 採否 | 理由 |
|---|---|---|
| NDL サーチ | 採用 | 件名、NDC、ISBN、刊行年月、出版社、シリーズ、注記、ページ数が取れる。NDL 作成の書誌データは PDL1.0 で、申請なしで使える(出典表示が必要) |
| openBD | 不採用 | 2023-06 に出版社由来のデータ提供が止まり、NDL 由来に切り替わった。試した 3 件で内容紹介と目次が空だった |
| Google Books | 不採用 | Google APIs Terms 5.e が DB の構築や恒久的なコピーを禁じている |
| 楽天ブックス | 不採用 | 規約上キャッシュは 3 か月までで、利用目的は商品紹介と楽天へのリンクに限られる(FAQ の抜粋で確認)。CLI から呼べるかも未確認 |

概要と目次は扱わない。保存できる取得元が見つからないため。

## 標本測定

非マンガ 29 冊とマンガ 21 冊を NDL サーチで照合した結果(2026-09 実施、判定は 1 人の目視)。

| 項目 | 非マンガ | マンガ |
|---|---|---|
| 正しい紙版に当たった | 26/29 | 17/21 |
| 当たった本に件名があった | 21/26 | 0/17 |

- 書名と著者だけで候補が 1 件に絞れたのは 29/50。Kindle 書名のレーベル、版表記、叢書番号も使うと 38/50。
- 同じ巻の紙版が複数当たったのは 9/50。
- ISBN と NDC は、当たった 43 冊中 42 冊に付いていた。NDC は 10 版の記号が多数派だった。
- 1.2 秒間隔では約 20 件目で HTTP 429 が返り、3 秒間隔では返らなかった。

## 要件

### 対象

- 全冊を対象にする。照合できない本(インディーズ作品、紙版のない本など)には何も付けない。
- 対象は `v_books` への WHERE 句で絞り込める。最初は非マンガから取得する。件名が付くのは非マンガだけなので、得られるものの大きい側から始める。

### 照合

精度を優先する。誤った書誌情報を付けるより、何も付けないほうを選ぶ。Claude が誤った刊行年月や件名をもとに答えるほうが、「情報なし」と答えるより害が大きいため。

- 書名を正規化して検索する(全角半角の統一、`【電子版】` などの除去、レーベル名の括弧書きの除去)。
- 著者名は検索条件にだけ使い、採用の判定では比べない。NDL は `Kahneman, Daniel, 1934-2024`、Kindle は `ダニエル・カーネマン` のように表記が違い、比べると翻訳書が落ちるため。
- 候補を数える前に、同じ作品を指すかを書名で確かめ、指さない候補は捨てる。NDL サーチの `title` は部分一致なので、検索語を含む別作品(『ファスト&スロー』に対する雑誌記事や、書名に同じ語を含む別の本)も返るため。同じ作品とみなすのは、Kindle 書名と候補の書名を同じ規則で正規化し(巻数、レーベル名、空白、記号を除く)、候補の本タイトル(NDL の `主題 : 副題` の主題)か、本タイトルと副題を連結したものが、Kindle 書名と完全に一致する場合に限る。前方一致や包含では同じ作品とみなさない。
- 同じ作品を指す候補が 1 件も残らなければ、照合は「見つからない」とする。検索語を含む別作品が 1 件だけ返っても採用しない。
- 巻数がある本は、巻数も一致した候補だけを残す。叢書番号(例: 「谷口ジローコレクション18」の 18)を巻数と取り違えない。
- Kindle 書名のレーベル、版表記、叢書番号で候補を絞る。
- 候補の紙版が 1 つに定まれば、作品の属性と版の属性をすべて採用する。
- 紙版が複数残った場合、作品の属性は全候補で値が一致したときだけ採用し、版の属性は採用しない。単行本と文庫のように、同じ作品の紙版が複数あることはよくあり(標本で 18%)、紙版の特定を必須にすると件名まで失うため。
- JPRO 由来の電子書籍の書誌は、紙版の候補から除く。「理想のヒモ生活」では 264 件中 238 件が電子書籍の分冊版の書誌で、紙版の巻が検索結果の 1 ページ目に入らなかった。

### 検索結果の取得

一部の候補だけで照合すると、紙版が複数あるのに 1 つと判断したり、あるのに「見つからない」と保存したりする。このため、検索結果をすべて見たときだけ照合する。

- 1 回の検索は `cnt=500` で取る。NDL サーチは既定で 200 件を返し、1 回の最大は 500 件、501 件目以降は `idx` を使っても取れない(外部提供インタフェース仕様書 第 1.4 版 §4)。
- 書名の検索は段に分けて、狭い条件から順に行う(書名と著者 → 書名だけ → シリーズ名と著者)。
- 段ごとに、応答の総件数が 500 件以下なら、その段の検索結果をすべて見たとみなす(段が「解消した」)。
- 総件数が 500 件を超えたら、同じ段の中で条件を足して検索し直す。足す順は、著者、巻数の語(電子書籍の書誌は最初の検索から除く。「下調べで確かめた事実」を参照)。途中で 500 件以下になれば、その段は解消したとみなし、最後の検索の結果だけを使う。最後まで 500 件を超えたら、その段は「未解消」とする。途中の検索が超過したことは、段の結論に影響しない。
- 解消した段の結果に採用条件を適用する。採用条件は、紙版であること、同じ作品を指すこと、巻数がある本は巻数が一致すること。採用条件を満たす候補が 1 件以上残った段で検索を止める。同じ作品を指す候補があっても、別の巻しか残らなければ次の段へ進む。
- 本の状態は、すべての段を見たうえで次のように決める。
  - 採用条件を満たす候補が残った段があれば「見つかった」。
  - そうでなく、未解消の段が 1 つでもあれば「保留」。保留した本には何も付けず、`kindb status` で件数を示す。手動訂正で ISBN を指定すれば救える。
  - すべての段が解消し、採用条件を満たす候補が 0 件なら「見つからない」。例えば、最初の検索が 800 件、絞り直すと 100 件で候補 0 件の段は解消しているので、ほかの段も同様なら「見つからない」になる。

### 手動訂正

- ASIN と ISBN の 2 列からなる CSV で、照合先を指定できる。
- ISBN を指定した本は、書名検索をせず ISBN で NDL サーチを引く。
- ISBN を空にした本は照合しない。
- 照合ルールを厳しくしても、大事な本を手で救えるようにするため。
- 訂正は DB に保存し、CSV を渡されたら全件を置き換える。置き換えるとき、前回と内容が変わった本は次のように扱う。
  - ISBN を足した、または変えた本: 取得の状態、保存済みの候補、照合結果を消して未取得に戻す。次の取得で、指定された ISBN で引き直す。保存済みの候補に、訂正先の紙版が入っているとは限らないため。
  - ISBN を空にした本: 保存済みの候補と照合結果を消し、状態を「照合しない」にする。
  - 訂正の行を消した本: 取得の状態、保存済みの候補、照合結果を消して未取得に戻し、書名検索からやり直す。
  - 候補も消すのは、`--where` や `--limit` で引き直されないまま再照合したときに、古い訂正で取った候補から採用し直さないようにするため。
- 訂正を変えられるのは、取得(`kindb enrich`)だけにする。再照合は通信しないので、新しい ISBN の紙版を取りに行けないため。

### 保存する書誌情報

| 項目 | 種別 | 備考 |
|---|---|---|
| 件名 | 作品の属性 | 複数 |
| NDC | 作品の属性 | 記号と版(8 / 9 / 10 / 不明)。標本には `NDC8:913.6` や、版のない `NDC:509.6` もあった |
| NDC 分類名 | 作品の属性 | 上位 3 桁から導く |
| 原題などの注記 | 作品の属性 | |
| ISBN | 版の属性 | |
| 紙版の刊行年月 | 版の属性 | NDL の記載の精度のまま。日付型にして存在しない日を補わない |
| 出版社 | 版の属性 | |
| ページ数 | 版の属性 | |
| シリーズ名(叢書名) | 版の属性 | |

NDLC は保存しない。記号から分類名を引く機械可読の表が見つからず、NDC と役割が重なるため。

### NDC 分類名

- NDC 記号の上位 3 桁を、日本図書館協会が CC-BY で公開している NDC9 のデータで分類名に変換する。10 版の表(MRDF10)は有償のため使わない。
- 変換表はリポジトリに同梱する。実行時の通信をなくし、配布元の URL の変更に左右されないため。
- 同梱するのは、生成した 3 桁の変換表だけにする。配布元の `ndc9.ttl`(7.6MB)はリポジトリに入れず、生成のときにリポジトリの外からパスで渡す。
- 分類名は配布データの表記(`漫画．挿絵．童画` のような全角の区切り)のまま使う。
- ttl ファイルの中にはライセンスの記載がなく、CC-BY の根拠は日本図書館協会の配布ページ(https://www.jla.or.jp/committees/bunrui/ndc-data/)。

### 候補の保存と再照合

- 検索を止めた段(ISBN 指定なら ISBN の検索)で返った候補の書誌を保存する。照合ルールを直したとき、NDL サーチに問い合わせ直さずに照合だけやり直せるようにするため。全冊の取得には数時間かかる。
- 本を引き直したら、その本の保存済みの候補はすべて置き換える。
- 候補が見つからなかった本も「見つからなかった」と記録し、次回からは引き直さない。明示的に指定したときだけ、「見つからない」と「保留」の本を引き直す。NDL の書誌は後から追加されることがあるため。
- 取得と再照合の役割を分ける。
  - 取得(`kindb enrich`): 訂正の置き換え、NDL サーチへの問い合わせ、候補の保存、照合を行う。
  - 再照合(`kindb rematch`): 保存済みの候補と保存済みの訂正だけを使って、照合をやり直す。通信せず、訂正も変えない。対象は状態が「見つかった」本だけで、未取得、「照合しない」、「見つからない」、「保留」の本は扱わない。
  - 再照合で直せるのは、保存済みの候補の中での判定だけ。検索の段や条件を変える修正は、引き直さないと反映されない。
- 検索の段や条件を直したときのために、状態によらず対象の本を引き直す指定を設ける。対象は `--where` と `--limit` で絞れる。「照合しない」の本は引き直さない。
- 引き直しで通信に失敗した本は、前回の状態、候補、照合結果を残す。一時的な失敗で、取れていた書誌情報を失わないようにするため。

### 取得の実行

- 取得先の負荷を所要時間より優先する。問い合わせは直列で 1 本ずつ、既定で 3 秒以上の間隔を空ける。NDL の API 仕様書(第 1.4 版)に OpenSearch のアクセス間隔の定めは見当たらず、3 秒は標本測定の実測値。
- HTTP 429 が返ったら待ってから再試行する。`Retry-After` があれば従う。
- 取得中は DB を開かない。一定冊数ごとに短時間だけ書き込み接続を開いてまとめて書く。取得は数時間かかり、その間ずっと書き込み接続を持つと、読み取り系コマンドや MCP サーバが DB を開けなくなるため。
- 中断しても、次の実行は最後に書き込んだところから再開する。

### 問い合わせでの使い方

- `v_books` に書誌情報の列を足す。Claude が最もよく使う入口であるため。
- `kindb search` の検索対象に件名を加える。書名にその語がなくても、件名で本を拾えるようにするため。

### 取り込みとの関係

- 書誌情報は専用のテーブルに保存し、`kindb import` と `kindb import-official` はこれに触れない。書誌情報は刊行後ほぼ変わらず、取得に時間がかかるため、主データの全件置換のたびに消すべきではない。
- 蔵書から消えた本の書誌情報はテーブルに残ってよい。ビューは `books` との結合で除外する。

### 出典表示

- NDL サーチ由来であること、加工したことを README に書く。
- NDC 分類名の変換表に、日本図書館協会のデータであることと CC-BY である旨を添える。

### 外部への送信

書名、著者、ISBN を NDL サーチに送る。蔵書 1 冊ずつの問い合わせでも、全体として蔵書の一覧に近い情報が送られることは許容する。

## 下調べで確かめた事実

実装の初期(2026-09-27)に確かめた。

- `dpid=iss-ndl-opac` でも `mediatype=booklet` でも、JPRO の電子書籍の書誌を検索段階で除ける。「理想のヒモ生活」は指定なしで 279 件(うち電子書籍 238 件)、どちらを指定しても同じ 41 件(すべて NDL の紙の図書)になった。
- 検索には `dpid=iss-ndl-opac` を最初の検索から付け、NDL 自身の書誌(ID が `R100000002-` で始まる)だけを候補にする。理由は次のとおり。
  - 標本の正解 43 冊は、すべて NDL 自身の書誌だった。
  - ほかの提供元の書誌は、同じ紙版でも内容が食い違う。『HARD THINGS』の ISBN 検索では NDL と CiNii の 2 件が返り、NDC は 336 と 335.13 で違い、CiNii の型なし `dc:subject` には著者名が入っていた。件名を NDLSH として扱えるのは NDL の書誌だけ。
  - ISBN のない古い本は提供元ごとに別の書誌で返り、紙版が複数あるように見えて版の属性を失う(標本の「トヨタ生産方式」)。
  - NDL がまだ所蔵していない新刊などは「見つからない」になる。NDL の書誌は後から追加されるので、引き直しで拾う。
- 電子書籍を最初の検索から除くので、総件数 500 件超の絞り直しで足すのは著者と巻数の語になる。巻数の語は `title` に空白区切りで足せば効く(「理想のヒモ生活 25」で 1 件)。
- `isbn` は 10 桁でも 13 桁でも引ける(『HARD THINGS』で確認)。
- `dpid` を付けても、応答に録音資料などが混ざることがある(「星界の紋章 2」に CD ブック)。`<category>` に「図書」と「紙」を持つ書誌だけを紙版の候補にする。
- 日本図書館協会の配布ページは、ライセンスを「CC-BY」とだけ書き、版番号を書いていない。提供者は分類委員会、ページの更新日は 2025-11-12。
- NDL サーチのデータプロバイダ一覧(https://ndlsearch.ndl.go.jp/help/api/provider)は、`iss-ndl-opac` のメタデータの利用条件を非営利、営利とも CC BY とし、国立国会図書館が作成する書誌データの二次利用条件は CC BY 4.0 と互換だと注記している。API の利用条件(https://ndlsearch.ndl.go.jp/help/api)は、API を用いていることの明記を求めている。README の出典はこの 2 つに合わせた。
- NDC9 の ttl で 3 桁の記号を持つのは 940 件で、`ndcv:Section` が 876 件、`skos:Concept` が 56 件(841〜888、971〜988。分類名に `＠` を含む)、別法の `ndcv:Variant` が 8 件。別法は NDL の書誌で使われないので除き、932 件を変換表にした。標本の NDL の書誌に出た NDC の上位 3 桁 25 種は、すべて引ける。
- hatchling は `src/kindb/data/` の TSV を wheel に含める。editable インストールではリポジトリの TSV を読む。

## 未確認の事実

- NDC9 の上位 3 桁の分類名が、NDC10 の同じ 3 桁と意味の上で一致するか。標本の 10 版の記号 17 種は、すべて 9 版の表で 3 桁の名前が引け、見た目には妥当だった(例: 675 マーケティング、798 室内娯楽)。意味のずれがないことまでは確かめていない。
- 全冊の実際の所要時間。標本からの見積もりは 3〜4 時間。
- NDL 作成の書誌データのローカル保存を明示的に許す文言。PDL1.0 の性質から保存できると解釈している。
