# 書誌情報の追加 要件

蔵書に NDL サーチの書誌情報(件名、NDC、紙版の刊行年月、出版社など)を付け、Claude が SQL で蔵書を探すときの手がかりを増やす。語の意味は `docs/glossary.md` に従う。実装後、確定した仕様は `docs/spec.md` に移し、本書はその理由と経緯の記録として残す。

## 背景と前提

- Kindle ASIN から ISBN を得る正攻法はない。Amazon の PA-API 5.0 は廃止され、後継の Creators API は直近 30 日で適格売上 10 件が利用条件のため、個人のツールでは使えない。商品ページの取得は規約で禁止されている見込み。このため、書名と著者で NDL サーチを検索して紙版に照合する。
- 蔵書 2,712 冊のうち約 73% はジャンル「コミック・ラノベ・BL」に属する。ただし `genres` が空のマンガもあり、ジャンルだけではマンガを判別しきれない。

## 取得元

NDL サーチの OpenSearch だけを使う。

| 候補 | 採否 | 理由 |
|---|---|---|
| NDL サーチ | 採用 | 件名、NDC、ISBN、刊行年月、出版社、シリーズ、注記、ページ数が取れる。NDL 作成の書誌データは PDL1.0 で、申請なしで使える(出典表示が必要) |
| openBD | 不採用 | 2023-06 に出版社由来のデータ提供が止まり、NDL 由来に切り替わった。試した 3 件で内容紹介と目次が空だった |
| Google Books | 不採用 | Google APIs Terms 5.e が DB の構築や恒久的なコピーを禁じている |
| 楽天ブックス | 不採用 | 規約上キャッシュは 3 か月までで、利用目的は商品紹介と楽天へのリンクに限られる(FAQ の抜粋で確認)。CLI から呼べるかも未確認 |

概要と目次は扱わない。保存できる取得元が見つからないため。

## 標本測定

非マンガ 29 冊とマンガ 21 冊を NDL サーチで照合した結果(2026-09 実施、判定は 1 人の目視)。

| 項目 | 非マンガ | マンガ |
|---|---|---|
| 正しい紙版に当たった | 26/29 | 17/21 |
| 当たった本に件名があった | 21/26 | 0/17 |

- 書名と著者だけで候補が 1 件に絞れたのは 29/50。Kindle 書名のレーベル、版表記、叢書番号も使うと 38/50。
- 同じ巻の紙版が複数当たったのは 9/50。
- ISBN と NDC は、当たった 43 冊中 42 冊に付いていた。NDC は 10 版の記号が多数派だった。
- 1.2 秒間隔では約 20 件目で HTTP 429 が返り、3 秒間隔では返らなかった。

## 要件

### 対象

- 全冊を対象にする。照合できない本(インディーズ作品、紙版のない本など)には何も付けない。
- 対象は `v_books` への WHERE 句で絞り込める。最初は非マンガから取得する。件名が付くのは非マンガだけなので、得られるものの大きい側から始める。

### 照合

精度を優先する。誤った書誌情報を付けるより、何も付けないほうを選ぶ。Claude が誤った刊行年月や件名をもとに答えるほうが、「情報なし」と答えるより害が大きいため。

- 書名を正規化して検索する(全角半角の統一、`【電子版】` などの除去、レーベル名の括弧書きの除去)。
- 著者名は検索条件にだけ使い、採用の判定では比べない。NDL は `Kahneman, Daniel, 1934-2024`、Kindle は `ダニエル・カーネマン` のように表記が違い、比べると翻訳書が落ちるため。
- 巻数がある本は、巻数も一致した候補だけを残す。叢書番号(例: 「谷口ジローコレクション18」の 18)を巻数と取り違えない。
- Kindle 書名のレーベル、版表記、叢書番号で候補を絞る。
- 候補の紙版が 1 つに定まれば、作品の属性と版の属性をすべて採用する。
- 紙版が複数残った場合、作品の属性は全候補で値が一致したときだけ採用し、版の属性は採用しない。単行本と文庫のように、同じ作品の紙版が複数あることはよくあり(標本で 18%)、紙版の特定を必須にすると件名まで失うため。
- JPRO 由来の電子書籍の書誌は、紙版の候補から除く。「理想のヒモ生活」では 264 件中 238 件が電子書籍の分冊版の書誌で、紙版の巻が検索結果の 1 ページ目に入らなかった。

### 手動訂正

- ASIN と ISBN の 2 列からなる CSV で、照合先を指定できる。
- ISBN を指定した本は、書名検索をせず ISBN で NDL サーチを引く。
- ISBN を空にした本は照合しない。
- 照合ルールを厳しくしても、大事な本を手で救えるようにするため。

### 保存する書誌情報

| 項目 | 種別 | 備考 |
|---|---|---|
| 件名 | 作品の属性 | 複数 |
| NDC | 作品の属性 | 記号と版(9 / 10) |
| NDC 分類名 | 作品の属性 | 上位 3 桁から導く |
| 原題などの注記 | 作品の属性 | |
| ISBN | 版の属性 | |
| 紙版の刊行年月 | 版の属性 | NDL の記載の精度のまま。日付型にして存在しない日を補わない |
| 出版社 | 版の属性 | |
| ページ数 | 版の属性 | |
| シリーズ名(叢書名) | 版の属性 | |

NDLC は保存しない。記号から分類名を引く機械可読の表が見つからず、NDC と役割が重なるため。

### NDC 分類名

- NDC 記号の上位 3 桁を、日本図書館協会が CC-BY で公開している NDC9 のデータで分類名に変換する。10 版の表(MRDF10)は有償のため使わない。
- 変換表はリポジトリに同梱する。実行時の通信をなくし、配布元の URL の変更に左右されないため。

### 候補の保存と再照合

- 検索で返った候補の書誌を保存する。照合ルールを直したとき、NDL サーチに問い合わせ直さずに照合だけやり直せるようにするため。全冊の取得には数時間かかる。
- 候補が見つからなかった本も「見つからなかった」と記録し、次回からは引き直さない。明示的に指定したときだけ引き直す。NDL の書誌は後から追加されることがあるため。

### 取得の実行

- 取得先の負荷を所要時間より優先する。問い合わせは直列で 1 本ずつ、既定で 3 秒以上の間隔を空ける。NDL の API 仕様書(第 1.4 版)に OpenSearch のアクセス間隔の定めは見当たらず、3 秒は標本測定の実測値。
- HTTP 429 が返ったら待ってから再試行する。`Retry-After` があれば従う。
- 取得中は DB を開かない。一定冊数ごとに短時間だけ書き込み接続を開いてまとめて書く。取得は数時間かかり、その間ずっと書き込み接続を持つと、読み取り系コマンドや MCP サーバが DB を開けなくなるため。
- 中断しても、次の実行は最後に書き込んだところから再開する。

### 問い合わせでの使い方

- `v_books` に書誌情報の列を足す。Claude が最もよく使う入口であるため。
- `kindb search` の検索対象に件名を加える。書名にその語がなくても、件名で本を拾えるようにするため。

### 取り込みとの関係

- 書誌情報は専用のテーブルに保存し、`kindb import` と `kindb import-official` はこれに触れない。書誌情報は刊行後ほぼ変わらず、取得に時間がかかるため、主データの全件置換のたびに消すべきではない。
- 蔵書から消えた本の書誌情報はテーブルに残ってよい。ビューは `books` との結合で除外する。

### 出典表示

- NDL サーチ由来であること、加工したことを README に書く。
- NDC 分類名の変換表に、日本図書館協会のデータであることと CC-BY である旨を添える。

### 外部への送信

書名、著者、ISBN を NDL サーチに送る。蔵書 1 冊ずつの問い合わせでも、全体として蔵書の一覧に近い情報が送られることは許容する。

## 未確認の事実

実装の初期に確かめる。

- OpenSearch の `mediatype` や `dpid=iss-ndl-opac` の指定で、JPRO の電子書籍の書誌を検索段階で除けるか。
- NDC9 の上位 3 桁の分類名が、NDC10 の同じ 3 桁と一致するか。
- 全冊の実際の所要時間。標本からの見積もりは 3〜4 時間。
- NDL 作成の書誌データのローカル保存を明示的に許す文言。PDL1.0 の性質から保存できると解釈している。
